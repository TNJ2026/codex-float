# ChatGPT 会话（实验性）

当前暂停此功能：窗口只显示 Codex 会话，不挂载来源标签或 ChatGPT 界面，后端也不注册 ChatGPT 命令。以下内容保留为实验接入记录。

窗口顶部的 **ChatGPT** 入口使用主 App 的 App Tools 通道读取会话列表和历史。默认手动同步；点击「手动同步」可开启每 10 秒自动同步，读取失败后不自动重试。支持加载更多会话、较早消息和向已存在的 ChatGPT 会话发送文字。切回 Codex 时保留两边的输入草稿。

模型选择、附件、停止生成和工具审批仍在主 App 中操作。App Tools 历史读取每页最多 10 轮，每项最多 20000 字符，较长内容可能被截断；完整内容以主 App 为准。此入口不创建会话，不会自动发送测试消息；发送超时后应刷新核对结果，避免重复发送。

此功能依赖主 App 启动环境提供的 `CODEX_APP_TOOLS_PIPE_PATH` 与 `CODEX_THREAD_ID`。悬浮窗使用真实调用方身份，保留主 App 的访问检查，不读取登录凭据，也不扫描其他进程。普通快捷方式独立启动时可能没有这些环境信息，此时会显示接入不可用，Codex 功能继续使用原有通道。

该通道属于主 App 的内部集成，版本更新可能改变行为。当前 Windows 已通过真实会话列表和历史的只读接入检查；真实消息发送需由用户在界面输入并触发，未自动向用户聊天发送测试提示。macOS 代码使用同样的本地通道，尚未实机验证。

## 选项卡片接入验证

当前主 App 内部的 `client_defined_widget` 支持 `ask_user_input` / `ask_user_input_v2` 问卷，包括单选、多选和自由输入。原生答复依赖源消息及请求标识，例如 `request_id`、`question_ids`，不能用普通文字发送代替卡片提交。

已检查当前运行 App 的全部 56 个 App Tools：没有针对现有 ChatGPT 会话读取卡片或提交卡片答案的操作。`read_thread` 的内部转换只保留 `userMessage` / `agentMessage` 的文字，卡片元数据及工具请求没有传出；`includeOutputs` 不会恢复已丢弃的原始元数据。真实历史读取也只返回了这些文字消息结构。现有 `request_environment_input`、`request_onboarding_input` 用于各自的输入流程，并不是 ChatGPT 卡片答复通道。

因此当前版本尚未接入原生选项卡片。需要主 App 提供包含选项、请求状态和标识的读取通道，以及对应的答复操作后，才能正确呈现和提交。此次验证未创建测试会话、未发送消息，也未提交任何卡片答案。
